# Notionタスク編集・AI記録連携

アプリの`index.html`と、既存の同期GASに追加する`notion-bridge.gs`を組み合わせます。
Notionトークン・対象DB IDはGASのスクリプトプロパティにだけ保存します。
アプリが読み込む対象や編集先を、リクエスト側から任意のDBへ変更することはできません。

## 既存GASへの追加

1. 現在の同期GASのコードとデプロイ設定を控えます。既存ファイルを置き換えないでください。
2. GASにスクリプトファイルを1つ追加し、`notion-bridge.gs`の内容を貼り付けます。
3. 既存の`doGet(e)`の先頭に次を追加します。既存の処理はそのまま残します。

   ```js
   const notionResponse = rvtNotionGet(e);
   if (notionResponse) return notionResponse;
   ```

4. 既存の`doPost(e)`の先頭に次を追加します。

   ```js
   const notionResponse = rvtNotionPost(e);
   if (notionResponse) return notionResponse;
   ```

5. プロジェクトの設定 → スクリプトプロパティを設定します。

   | 名前 | 値 |
   | --- | --- |
   | `NOTION_TOKEN` | 対象ページに接続したNotionインテグレーションのトークン。既存の`NOTION_API_KEY`も利用可 |
   | `RVT_NOTION_KEY` | アプリの連携用合言葉。省略時はスクリプトプロパティ`SECRET`、次に既存コードの文字列定数`SECRET`を利用 |
   | `RVT_NOTION_TASK_SOURCE` | 編集するタスクDBまたはデータソースのID |
   | `RVT_NOTION_RECORD_SOURCE` | AIに読ませる記録DB・データソース・ページのID |
   | `RVT_NOTION_COMMENT_SOURCE` | AIコメントの保存先DB・データソース・親ページのID |

   複数のデータソースを含むDBでは、DB IDではなく対象のデータソースIDを指定します。
   利用しない機能の対象IDは省略できます。Notion側で対象DBを同じインテグレーションへ接続し、
   読み込み・タスク更新・新規ページ作成に必要な権限を設定します。

6. GASエディタから`rvtNotionCheckSetup`を実行し、タスクDBとコメント保存先を読み取れることを確認します。
   この確認はタスク更新やページ作成を行いません。実際の書き込み権限は保存時に確認されます。
7. **デプロイを管理 → 既存のウェブアプリを編集 → 新バージョン**で更新します。
   新規デプロイは作らず、既存の`/exec` URLを維持します。
8. アプリの設定 → Notion連携 → 接続確認を実行します。
   連携URL・合言葉が空欄なら既存の端末間同期設定を使います。

## タスクの項目

タスクDBのスキーマを読み込み、以下の項目だけを編集します。
別名の場合は、対応するスクリプトプロパティで名前を変更できます。

| 設定名 | 既定のプロパティ名 | 対応するNotion型 |
| --- | --- | --- |
| `RVT_NOTION_TASK_TITLE` | 名前（未検出時はtitle型を検出） | title |
| `RVT_NOTION_TASK_STATUS` | ステータス | select / status |
| `RVT_NOTION_TASK_DUE` | 締め切り | date |
| `RVT_NOTION_TASK_PRIORITY` | 優先度 | select |
| `RVT_NOTION_TASK_MEMO` | 備考・注意事項 | rich_text |

メモは上記のプロパティを編集します。ページ本文のブロックを置き換える機能ではありません。
変更した項目だけをPATCHし、未編集のリッチテキスト・関連・その他のプロパティは維持します。
期限は日付のみ・日付と時刻に対応します。期間や名前付きタイムゾーンのある期限はNotionで編集します。
保存前に最終編集日時を確認し、変更されていた場合は停止します。
Notion APIにはこの処理で使える原子的な条件付き更新がないため、同時編集を完全には防げません。
保存後の再取得で内容を検証してから完了を表示します。

## AIの材料とコメント保存

- AI設定で「Notionの記録もAIに送信」をONにすると、生成前に記録DBを読み込みます。
- 更新日時を対象期間で絞り、DBなら最大10ページ、ページ指定ならそのページを取得します。本文の子ブロックは深さ2、最大100ブロックまで。
  長い本文や取得対象外の部分は抜粋となり、アプリに省略を表示します。
- プロパティと本文をテキストとして扱い、メモ内の命令は実行しません。
- 全送信データは既存の最大120件・約3万文字の枠内に収め、送信プレビューへ表示します。
- 生成結果の「このコメントをNotionに保存」で、保存先DBに新規ページを作成します。親ページ指定なら、その配下にコメント用の子ページを作成します。
  既存ページを上書きせず、タイトル・本文・対象記録の件数を保存します。
- 同じコメントIDで成功した保存は再作成せず、保存先URLを返します。
  通信断などで結果が不確定な保存は自動再送せず、Notion側の確認を案内します。
- 保存済みURLはアプリのコメントに保持し、クラウド同期します。

不確定保存は`RVT_NOTION_SAVED_<コメントID>`が`pending`として残ります。
Notion側を確認し、作成済みならそのプロパティを作成済みページURLに変更します。
未作成が確認できた場合に限り、そのプロパティを削除してから再試行できます。

## 動作確認

`node tests/notion-bridge.test.cjs`で、外部通信をしないGASのテストを実行できます。
実運用では接続確認・読み込みを行い、編集は合意したテスト用タスクで確認します。
同期GASの既存のアップロード・取得・CSV更新・カレンダー連携も更新前後に確認してください。
