# 食行動支援 v3 設計書 — 想起（記録がその場で返ってくる）

対象: `itwrk/routine-timer` / `main`
基準: v2実装＋同期強化後（`6c906c1`、index.html 3664行）
前提資料: `docs/food-support-design.md`（v1）/ `docs/food-support-v2-design.md`（v2）。原則・禁止事項はすべて引き継ぐ。
実装手順: `docs/codex-food-support-v3-handoff.md`

## 1. なぜv3が必要か — v2設計の誤り

実使用2日目（2026-08-02 夕方）、Halは**1件も記録しなかった**。理由は本人の言葉で:

> なんかやるメリットを感じなかった。なので、実行しませんでした。

その日の実際の出来事:

```
夫に鮭弁当を頼む → 気力があったので味噌汁を作る（湯・味噌・ほんだし・長ネギ）
弁当のご飯が少ない → 100gご飯をレンチンして足す
味噌汁から飲む → 鮭弁当を夢中で食べる「うますぎ」
水を飲む → まだ足りない → めかぶ → まだ食べたい
冷蔵庫を漁る → 良さそうなものがない
18:55 空腹が続く → ゲームをする → 19:12 一旦落ち着く
```

記録に値する出来事は十分あった。**アプリを開かなかっただけ**である。

### 何を間違えたか

v2は「予報は第3段階。データが少ないうちは断定しない」と決めた。原則は正しいが、**順序が誤っていた**。

```
記録が貯まるまで何も返さない → 返らないから記録が続かない → だから貯まらない
```

初日の「⚡めちゃいい」は**新規性による報酬**であり、1日で切れた。返りを後回しにできる前提が崩れている。

### 転換点 — 「予報」ではなく「想起」

Halが挙げた「押した甲斐がある返り」は次の2つだった。

- 今日の流れが見える
- 前に同じ状態のとき何をしたか思い出せる

**どちらも予測ではなく思い出しである。** ここが決定的だった。

| | 予報（v2で第3段階に置いたもの） | 想起（v3で作るもの） |
|---|---|---|
| 中身 | 「14時ごろ波が来やすい」 | 「今日はこう動いた」「前回はこうだった」 |
| 必要件数 | 数十件 | **1件から成立する** |
| 断定リスク | 高い（統計を装う） | **低い（事実を並べるだけ）** |
| 原則との整合 | 「少ないうちは出さない」に抵触 | **抵触しない** |

想起は記録が1件でも正直に返せる。「データが少ないうちは断定しない」を守ったまま、初日から価値を返せる。

**v3の一文:「記録した瞬間に、自分の記録が返ってくる」**

## 2. 返すもの（3つ）

### R1. 今日の流れ

今日の食事・衝動・起床を時系列で数行。

```
17:40 🍽 鮭弁当＋味噌汁
18:20 ⚡8 → 💧水
18:55 ⚡7 まだ続いてる
```

**既存の24時間タイムラインとの違い**: あれはホーム最下部にあり「わざわざ見に行くもの」。R1は**記録した直後にその場で更新され、目に入る位置にある**。

### R2. 似たときの記録（複数）

現在時刻と近い時間帯の過去の衝動を**最大3件**。

```
夕方ごろの記録
8/1 17:50 ⚡6 → 🥨めかぶ → 食べた
7/31 18:40 ⚡9 → 🎮別のこと → 22分で落ち着いた
7/30 18:10 ⚡8 → 💧水 → 17分で落ち着いた
```

**軸**: 第一が**時間帯**（現在時刻±2時間）、第二が**強さの近さ**。Halの実感が「夕方の波」だったため時間帯を主軸に置く。

**断定しない**: 「だから水を飲め」とは言わない。並べるだけ。助言も要約もしない。

**出す場所が2箇所ある**（後述）。特に**⚡で強さを選んだ直後**——これから何をするか決める、まさにその瞬間に出す。

### R3. ふりかえりカード（ホーム常設）

R1とR2を1枚にまとめ、ホームに常設する。記録していない時でも目に入る。

## 3. 情報設計

### 3.1 時間帯の扱い

**照合は現在時刻±2時間**（曜日は問わない）。固定バンドだと境界（18:55と19:12が別バンドになる等）で不自然になるため。

**表示は日本語のバンド名**を使う。

| バンド | 時刻 |
|---|---|
| 朝 | 5:00–9:59 |
| 昼 | 10:00–14:59 |
| 夕方 | 15:00–18:59 |
| 夜 | 19:00–22:59 |
| 深夜 | 23:00–4:59 |

見出しは「**夕方ごろの記録**」のように、照合の中心時刻が属するバンド名で出す。「ごろ」を付けることで厳密なバンド分類ではないことを示す。

### 3.2 似たときの選び方

```
候補 = urgeLogs のうち !deletedAt かつ 自分自身でない
  ↓ ①時間帯フィルタ: |時刻の差| ≤ 2時間（日をまたぐ 23:30 と 00:30 も近いとみなす）
  ↓ ②並べ替え: 強さの差が小さい順 → 同点なら新しい順
  ↓ ③上位3件
```

**フォールバック**（0件のとき）:
1. 時間帯を外し、強さの近い順で3件 → 見出しを「**近い強さの記録**」に変える
2. それも0件 → 「**まだ記録がありません。これが最初の1件になります。**」

**強さ未入力（null）の扱い**: 強さ差は最大値扱いにして後ろに回す。除外はしない。

### 3.3 1行の書式

```
{M/D} {HH:MM} ⚡{強さ} → {何をしたか} → {結果}
```

| 部位 | 出し方 |
|---|---|
| 何をしたか | `settledBy` のラベル（複数なら「・」区切り）／ `ate` なら `🥨{品目}` ／ どちらも無ければ省略 |
| 結果 | `settled`→「{n}分で落ち着いた」（`resolvedAt` があるとき）／「落ち着いた」／ `ate`→「食べた」／ `open`→「まだ続いてる」（`rechecks` があれば「×{n}」）／ `null`→「記録のみ」 |

**時間が出せるときは必ず出す。** 「17分で落ち着いた」は、次に待てるかどうかの最も具体的な材料になる。

## 4. 画面

### 4.1 配置

| 要素 | 位置 |
|---|---|
| `#recallCard`（ふりかえり） | **`#mealCard` の直下**、`#habitCard` の直上 |
| ⚡フロー内の想起 | 強さ選択後の画面で、3択ボタンの**上** |

ホーム上部の並び:

```
📝 ひとことメモ / 🌡️ 今の気分
🍽 食事カード（⚡）
🔎 ふりかえり          ← ★v3で追加
✅ 今日のチェックリスト
ルーチン一覧 / 今後の予定 / 24hタイムライン
```

**なぜ食事カードの直下か**: ⚡を押す→返りが出る、が視線移動なしにつながる。またチェックリストは項目数で高さが変わるため、その上に置いて位置を固定する（v1 §8-4と同じ理由）。

### 4.2 ふりかえりカード

```
┌─────────────────────────────────────────┐
│ 🔎 ふりかえり              すべて見る → │
│ ── 今日                                  │
│ 17:40 🍽 鮭弁当＋味噌汁                  │
│ 18:20 ⚡8 → 💧水                         │
│ 18:55 ⚡7 まだ続いてる                    │
│ ── 夕方ごろの記録                        │
│ 8/1 17:50 ⚡6 → 🥨めかぶ → 食べた        │
│ 7/31 18:40 ⚡9 → 🎮別のこと → 22分で…    │
└─────────────────────────────────────────┘
```

- 「今日」は最大5件（新しい順）。0件なら見出しごと省略。
- 「〜ごろの記録」は最大3件。
- **両方0件のとき**: `まだ記録がありません。⚡を押すと、ここに残ります。` の1行だけ。カードは消さない（存在を知ってもらうため）。
- 「すべて見る →」は `scr-meal`（食事サポート）へ。

### 4.3 ⚡フロー内の想起

強さを選んだ直後の画面（現在は「このあとはどうする？」＋文脈チップ＋3択）に、**3択の上**へ差し込む。

```
┌─────────────────────────────────────────┐
│ 夕方ごろ、このくらいのとき                │
│ 8/1 17:50 ⚡6 → 🥨めかぶ → 食べた        │
│ 7/31 18:40 ⚡9 → 🎮別のこと → 22分で…    │
│                                          │
│ (🏠家)(🚪外)(📺見ながら)(なし)           │
│ ┌────────────┐ ┌────────────┐          │
│ │🍽 食事にする│ │🥨 つまんだ  │          │
│ └────────────┘ └────────────┘          │
│ ┌────────────┐                          │
│ │👀 様子を見る│                          │
│ └────────────┘                          │
└─────────────────────────────────────────┘
```

**制約**: ここでは**最大2件**に抑える。3択ボタンが画面外に押し出されるとフローが重くなる（v2の「2〜4タップで完了」を壊さない）。フォントは小さめ、1件1行。

**見出し**: 「夕方ごろ、このくらいのとき」。時間帯と強さの両方で選んでいることが伝わる文言にする。

## 5. データモデル（schemaVersion: 4）

**新規コレクションなし。** v3はほぼ読み取り側の機能である。

### 5.1 UrgeLog への追加

| フィールド | 型 | 既定 | 意味 |
|---|---|---|---|
| `resolvedAt` | number(ms) \| null | null | `outcome` が `settled` / `ate` に確定した時刻。**「17分で落ち着いた」の算出に使う** |

`updatedAt` で代用しない。後から編集・同期で更新されると所要時間が壊れるため、確定時刻を独立して持つ。

### 5.2 URGE_SETTLERS への追加

今日の実例で「ゲームをした」が効いた可能性が高いが、既存6種（水・お茶・コーヒー・時間・動いた・その他）では表現できない。

```js
{id:'distract', label:'🎮 別のこと'}
```

`other` の前に挿入する。**IDは追加のみ。既存IDのラベル・順序は変えない**（過去データの意味が変わるため）。

### 5.3 マイグレーション

`migrateData()` に `if(from<4){}` は不要（`normalizeUrgeLog` の既定値補完で足りる）。`CURRENT_SCHEMA=4` に更新し、`normalizeUrgeLog` の `Object.assign` 既定へ `resolvedAt:null` を追加、`mealNumber` で検証する。

**旧データ（`resolvedAt` を持たない衝動）**: `null` のまま。所要時間は表示せず「落ち着いた」とだけ出す。**過去データを推測で埋めない。**

### 5.4 同期

`MERGE_COLLECTIONS` は変更不要（`urgeLogs` は既に対象）。GAS変更なし。

## 6. CSV

`buildUrgeCsv()` のヘッダ末尾に**1列追加**（末尾追加のため後方互換）。

| 列 | 値 |
|---|---|
| `収まるまでの分` | `resolvedAt` があれば `Math.round((resolvedAt - at)/60000)`、負値は空欄、無ければ空欄 |

ChatGPT用タイムラインCSVは**列を増やさない**。`urgeTimelineDetail()` の `結果:` に「（{n}分）」を添える形で表現する。

## 7. 文言

| 場面 | 文言 |
|---|---|
| カード見出し | `🔎 ふりかえり` |
| 今日の見出し | `今日` |
| 想起の見出し（カード） | `{バンド}ごろの記録` |
| 想起の見出し（⚡内） | `{バンド}ごろ、このくらいのとき` |
| フォールバック見出し | `近い強さの記録` |
| 記録ゼロ | `まだ記録がありません。⚡を押すと、ここに残ります。` |
| 想起ゼロ | `この時間帯の記録はまだありません。これが最初の1件になります。` |
| 遷移 | `すべて見る →` |

**禁止語はv1・v2と同一。** 加えてv3固有の禁止:

- **助言をしない**: 「水を飲むとよさそうです」「前回うまくいった方法です」等を書かない。**事実の列挙のみ。**
- **成否を含意しない**: 「落ち着いた」は事実。「うまくいった」は評価。後者を使わない。
- **件数を誇張しない**: 1件しかないときに「傾向」と書かない。

## 8. スコープ

### v3でやること

1. `resolvedAt` の記録、`distract` 設定値の追加
2. `similarUrges()` — 時間帯±2時間 → 強さ近接で最大N件
3. ふりかえりカード（今日の流れ＋似たときの記録）をホームに常設
4. ⚡フロー内（強さ選択後）に想起を最大2件
5. 衝動CSVに「収まるまでの分」

### v3でやらないこと（第2段階として保留）

今日の出来事から見えたが、**返りの改善を優先**するため今回は入れない。

| # | 保留する課題 | 内容 |
|---|---|---|
| S1 | **食事の組み立て** | 弁当（他人が調達）＋味噌汁（自作）＋足したご飯。いまは1つの `label` に収まらない |
| S2 | **食べる前の量調整** | 「ご飯が少ないから100g足した」——すでに起きている適応を置く場所がない |
| S3 | **食べる順番** | 「味噌汁から飲んだ」。汁物先行と追加欲求の関係 |
| S4 | **おいしさ・満足** | 「うますぎ」。いまは欲求しか測っていない。**正の体験の記録がない** |
| S5 | **探したが無かった** | 食べようとしたが環境になかった。`ate`/`settled`/`open` のどれでもない第4の結果 |

**S4は特に重要**として記録しておく。「味をもっと楽しみたい」タグがあるのに、実際に楽しめたかを残せないのは片手落ちである。

### 永久にやらないこと

v1 §27 のまま（カロリー・PFC・体重・食品DB・善悪判定・我慢のゲーム化）。

## 9. リスク

| リスク | 対策 |
|---|---|
| ⚡フローが重くなり、2〜4タップの軽さが壊れる | フロー内は**最大2件・1行ずつ**。3択が画面外に出ないことを375pxで実測する |
| 想起が「前と同じことをしろ」という圧に感じられる | 助言を書かない。並べるだけ。文言レビューで「した方がいい」を含む語を排除 |
| 1件しかないのに傾向のように見える | 見出しを「記録」に固定し、「傾向」「が多い」等を使わない |
| 返りが出ても、やはり記録が続かない | **v3投入後に再度Halの実感を聞く。** 続かなければ原因は返りではなく入力コスト（S1〜S5）にあると判断し、第2段階へ進む |
| `resolvedAt` が旧データに無く、所要時間が出ない | 推測しない。時間なしで表示。数日で自然に埋まる |

## 10. 受け入れ条件

1. ⚡→強さを選んだ時点で、過去の記録が最大2件その場に出る（0件なら案内文）
2. ホームの食事カード直下に、今日の流れと似たときの記録が常時見える
3. 「17分で落ち着いた」のように**所要時間が出る**（`resolvedAt` があるとき）
4. 記録が1件もない状態でもカードが壊れず、案内文が出る
5. 375px幅で⚡フローの3択ボタンが画面内に収まる
6. 想起の文言に助言・評価・傾向の語が含まれない
7. 既存の食事・衝動データが壊れず、CSVの既存列が不変
8. XP・コンボ・ストリーク・演出に一切接続されない
